# 接力台设计说明（2.0）

给以后改代码的人（和 AI）看的。用户手册见 [README](../README.md)。

## 为什么有接力台

一个人手上有好几个 AI：Claude、Codex（GPT）、Cursor、ZCode、MiMo、DeepSeek……每个都有额度。
常见的一天是这样的：

1. 先用 Claude 做一件事，做到一半额度用完了；
2. 转头在**同一个文件夹**里打开 Codex 接着做，又用完了；
3. 只剩 DeepSeek 能用。它便宜，但明显弱一些，怕它把代码改坏。

接力台要做到：**不管换哪个模型接着做，都不影响项目的进度、完成度和正确率。**

- **进度不丢**：谁一开工就知道任务是什么、做到哪了、上一棒留了什么话、哪里还没做完。
- **改动都有账**：每一棒改了哪些文件、自己说做了什么，都记下来；就算它额度用完被打断、没来得及留话，接力台也替它记一笔。
- **弱模型的活有人复核**：弱模型（比如 DeepSeek）做的每一棒自动标「待复核」。强模型（Claude、GPT……）额度恢复后，先对照它的交接把真实改动核一遍：说做了的是不是真做了、有没有改错，错的直接修好，再接着往下做。
- **改坏了能退回**：每一棒前后都有快照，可以退回到任何一棒之前。
- **不用动手**：可以自己在各个 AI 工具里接着干（接力台只管记账和提醒），也可以让接力台替你调度——额度用完自动换下一位，强模型额度恢复后自动去复核。

另外一个想法是**群聊**：既然有这么多 AI，就把它们拉进一个群，对同一件事各出主意；再加上**投票**，每个 AI 一票、方案匿名，弱模型的好想法也不会因为它弱被忽略。

## 1.x 哪里偏了

1.x 做成了「开任务 → 在项目外的隔离副本里干活 → 另一个 AI 审查 → 合回」的流水线。问题是：

- 你平时是**直接在项目文件夹里**打开 Codex、Claude 接着干的；隔离副本在别的地方，你手动换人时它们根本看不到。
- 每件事都要先在接力台里「开始任务」、最后「合回」，多出来很多点点点。
- 它关心的是「这一件事审完合回」，而你关心的是「换人之后能不能接得上、弱模型的活有没有人把关」。

2.0 改成：**就在项目文件夹里干活**，接力台在旁边记账、提醒、调度。

## 核心概念

| 叫法 | 是什么 |
|---|---|
| 接入 | 让一个文件夹开始接力：建 `.relay/`，在 `AGENTS.md` / `CLAUDE.md` 里加一段「接力规矩」（各家 AI 工具开工时都会读） |
| 接力本 | `.relay/接力本.md`，接力台生成的「开工必读」：任务、进度、上一棒的话、待复核、强弱名单、这一棒要做什么 |
| 任务 | `.relay/任务.md`：当前任务、进度清单、约定。AI 和你都可以改 |
| 棒 | 一个 AI 连续干的一段。第 1 棒、第 2 棒…… |
| 交接 | `.relay/交接/*.md`：每一棒结束时（最好边做边写）AI 自己写的话：做了什么、没做完的、不确定的地方、下一步 |
| 快照 | 整个文件夹的存档。存在 `.relay/snapshots/`（接力台自己的 git 仓库，**不碰你自己的 git**），每一棒前后各一张 |
| 待复核 | 弱模型做的、或者不知道是谁做的（没留交接）的棒；弱模型一个文件没改、只在清单里打了勾，也算（要确认那几步真做完了） |
| 复核 | 强模型对照交接看真实改动，把结论写进 `.relay/复核/第N棒.md`。「结论」一行只写五种之一：没问题 / 有问题，已修好 / 改坏了，已退回 / 有问题，还没修 / 证据不足。前三种才算复核过 |
| 验收 | 这件事能不能算做完了（`core/acceptance.ts`，全自动收工、网页顶部、接力本、`relay status` 都只看它）：清单全打勾、弱模型的棒都复核通过、终审通过、检查通过、证据都读得到 |
| 成员 | 这台电脑上认出来的 AI，一位就是一个模型：在编程工具（Claude Code、Codex、Cursor、ZCode……）或模型接口（DeepSeek、MiMo……）里跑，每位标「强」或「弱」。名字叫它用的模型（`core/names.ts` 的 `llmName`：gpt-6-sol → GPT-6 Sol） |

## 两种接着做的方式

### 自己接着做（在各家工具里）

接入后，什么都不用点：直接在项目文件夹里打开任意 AI 工具说「接着做」。

- `AGENTS.md`（Codex、Cursor、ZCode、MiMo 等都会读）和 `CLAUDE.md`（Claude Code 读）里有一段接力规矩，由接力台维护，前后有标记，不动你自己写的内容。
- 规矩只有几条：开工先读接力本、建交接文件；强模型接着先复核待复核的棒（先建交接再写复核，复核才认得出是谁写的）；边做边在任务里打勾；收工前写完交接。
- 接力台开着的时候，它在后台盯着这个文件夹：文件一有变化就存快照；发现新的交接就把这一棒记上账；一段改动之后 20 分钟没动静又没人交接，就当它被打断了，替它记一笔（标待复核）。
- 一棒从什么时候算起：它建交接文件的时候（文件的创建时间，接力台没开着时也对得上）；没有交接就是接力台看到改动的时候。开工前的任务清单用最近一次记下的（上一棒结束时、换任务时、退回后、接入时），不用接力台看到它时的——那时它可能已经打过勾了。

### 让接力台调度

网页上点「接着做」（或者换人），或者打开「全自动」：

- 接力台用这个工具的无人值守模式在**项目文件夹里**干一棒（Claude Code `-p`、Codex `exec`、Cursor Agent `-p`……；只有接口的模型用内置小代理）。
- 前后各存一张快照；它没写交接就用它最后说的话代写一份；跑检查命令；弱模型的棒标待复核。
- 检查命令自己在项目里写的文件（`.pytest_cache`、覆盖率报告……）：跑完存一张快照当新起点，账本记一笔 `base`（「检查命令写的文件：…」），不算到哪一棒头上，也不会被当成「有别的 AI 在改文件」。调度时（拿着锁）全算；盯文件夹时只有改的全是生成的文件（`snap.ts` 的 `generatedPath`）、或者检查命令里写明往里写的文件（`track.ts` 的 `gateWrites`：`> 文件`、`tee`、`-o`、`--junitxml=` 这类写入位置；命令里只是读的文件不算，免得把别的 AI 同时改的代码记掉）才这样记，改到了别的代码就照常算到下一棒。常见的测试缓存（`.pytest_cache/`、`.mypy_cache/`、`.coverage`……）本来就不进快照。
- 额度用完：只在工具出错退出、或者什么都没说就结束时才去认；认的时候只看工具自己报的话（出错信息、标准错误、日志里的「出错」「提示」，`runner.ts` 的 `toolLines`）和最后一句话，不看 AI 说的话、搜的词——任务本身讲限流、额度时那些话里全是 rate limit、quota。
- 接力台退出（Ctrl-C、kill、关掉终端窗口的 SIGHUP、网页上点关闭）：先叫停调度，等正在干活的工具真正结束（先 SIGTERM，5 秒后没停就强制结束，最多等 10 秒），这一棒记成「已停止」再退。被强行结束的话，下次 `relay ui` 启动时把上次留下的工具结束掉（进程号和命令都对得上才动）。
- 后台常驻（macOS，`scripts/make-desktop-app.sh`、`ops/keeper.ts`）：「接力台.app」是一个没有图标的 AppleScript 小程序（`LSUIElement`），放在 `/Applications`（没有写权限时 `~/Applications`；9-29 以前放 `~/Applications`，重装时旧的挪进废纸篓），登录时由 `~/Library/LaunchAgents/local.relay.login.plist` 在后台带起来。它必须一直开着（小程序一退出，系统会把它带起来的进程全部结束），每 10 秒用 `open-relay.sh --check` 看一眼：接力台没了就 `--background` 重新拉起（拉不起来过 5 分钟再试）；返回 3（你在网页上点了「关闭」，接力台留了 `~/.relay/ui-stopped`）就跟着退出。它拉起的接力台带 `RELAY_KEEPER=1`（不传给 AI 工具）：每 15 秒看一眼 `dist/src/cli.js`，编译出新版、连着两次一样（编完了）、手上没有调度、群聊、投票、检查在跑，就自己退出等小程序用新版拉起；网页看 `/api/state` 的 `build` 变了就自己刷新（你正在打字、开着弹窗或菜单时等空下来再刷）。`npm run build` 先编到 `dist.new` 再整体换上，接力台不会看到编到一半的结果。
- App 图标（2026-09-29 查清）：新版 macOS 的启动台（系统的「Apps」）第一次看到一个位置的程序时记下图标，之后不跟着换；以前安装脚本先在原位置编出带默认图标的小程序、一两秒后才换上图标，启动台正好记下那一刻（`~/Applications` 那一份一直是 9-24 第一版）。现在先在临时文件夹里把整个程序做好（图标、签名）再一下子挪进去；图标按新格式做（`scripts/AppIcon.icon` 编成 `Assets.car`，只给 icns 会被套一圈白底）；包标识换成 `local.relay.app`。已经记错的，把程序挪出去、等启动台把它去掉，再装回来（有新程序进来时启动台会重读一遍）。
- **全自动**：一直接着做，直到验收通过（不只是清单打勾）。
  - 额度用完（认得各家的提示），就记下什么时候恢复，换下一位；恢复时间先看工具报的用满了的窗口（精确到秒），没有才看提示里的话；
  - 额度还剩多少：每棒跑完、群聊答完，把工具自己报的额度窗口（5 小时、一周、一周 Opus 用了百分之几、什么时候恢复）记进 `~/.relay/quota.json` 的 `limits`（`quota.ts` 的 `noteLimits`；网页读 `/api/state` 成员的 `limits`、`limitsAt`，过了恢复时间的窗口给 0%、不带恢复时间）。Claude Code 用 claude.ai 登录时在 stream-json 里发 `rate_limit_event`（接口密钥不发）；Codex 记在自己的会话记录 `~/.codex/sessions/年/月/日/` 里（`harness.ts` 的 `codexSessionLimits` 取这一棒开始之后、在这个项目里的最新一份；群聊用的 `--ephemeral` 不留）。不读登录凭据、不联网、不花额度；别家不报的照旧只在用完时认。2026-09-28 用官方账号真跑过一次（Claude Code 2.1.282，haiku 答一句，约 0.016 美元）：报的是 `unifiedWindows` 里的 five_hour、seven_day，读出 5 小时 0%、一周 72%，原样存成测试（`limits.test.ts`）。网页只在成员名单里写（左下角成员叠点开的名单、设置里的成员）：名字底下那行「5 小时 5% · 一周 72%」（一周 Opus 写「Opus」），悬停看几点恢复（今天写几点、明天写「明天 00:30」、一周内写星期）；不变色、不加红点；
  - 挑人（`members.ts` 的 `spareFirst`）：同一档强弱里，报了额度的几位按一周额度哪天恢复重排，先恢复的先上（剩下的不用就作废了），位置还是它们原来占的那几个，没报额度的照设置里的顺序不动；有哪个窗口用了九成以上的挪到这一档最后，免得干到一半用完；调度时出过错的（`quota.json` 的 `errors`，`noteError`）也挪到这一档最后：第 1 次 1 分钟，连着错一次翻倍，最多 10 分钟，做成一棒就清掉（`markOk`）。借 magpie 的做法：代理节点不通时，不用每轮全自动都先等它错一次；
  - 有待复核、又有强模型能用，先派强模型复核；复核两次还没过（结论是有问题、证据不足、没写清楚），停下交给你；
  - 全都没额度了就等，等到最早恢复的那一位；
  - 清单打完后请强模型把整件事从头到尾过一遍（终审，最好换一位没干过活的）。终审算数要：交接成功、实际跑的是强模型、结论是「没问题」或「有问题，已修好」、终审之后没人再改文件。两次都不算数就停下；开着终审却请不到强模型、又不等，也停下，不会跳过终审说「完成」；
  - 配了检查命令：最后一次改动之后没跑过检查就补跑一次；检查没过就停下。
- **派活**：在网页「派活」页（或 `relay task --dispatch`）写的任务，账本的 `task` 事件记 `mode: 'dispatch'`（`ledger.ts` 的 `taskMode`），全自动就换一种派法（开始时定下，`relay auto --dispatch / --relay` 可以这一次改），强模型只花在拆解、复核、终审上。网页三页（`VIEWS`）：接力、派活两页按任务的 `mode` 分开列（`pageThreads`），线路还是按全部任务切（`rangeOf`）；每一棒结束时把日志里工具报的用量加起来记成 `tokens`（`runner.ts` 的 `usageTotal`），卡片上写 token 数，收尾写强、弱模型各用了多少（`tokenSplit`）。
  - 这个任务写下之后还没有交接了的「拆解」棒（`kind: 'plan'`，`go.ts` 的 `planned`）：先请强模型拆（`prompts.ts` 的 `planPrompt`），它只改 `.relay/任务.md`：每步一行，下面缩进写做法；不自己把活干一遍（2026-09-27 实测 Grok 在临时目录写完整份代码、跑通测试再把代码贴进清单，强模型的 token 反而没省下），项目里外都不写实现代码，步骤里不贴整段代码；只写要求，不写逐字的期望输出、整段模板和一条条测试用例，几行要点就够，清单一次写完（同日大任务实测：Grok 写了 34KB 的逐字规格、分 11 次追加，拆解一棒 93.0 万 token，比它直接做完整个任务的 51.3 万还多；改成「每步不超过 300 字」后清单只剩 9.7KB，但它写了 15 段脚本数字数、反复压缩，拆解涨到 270.2 万——提示里不写硬性字数）。`parseTask` 把缩进的行记在那一步的 `note` 上，网页在没做的步骤下面用小字显示；改清单（加一步、删一步）时做法跟着自己那一步走（`itemEnd`）。拆完清单还是空的就停下；拆的人出错、没交接，换一位强模型；
  - 干活只挑弱模型（`pick('weak')`），提示只给清单里的下一步（`stepPrompt`：只做这一步、做完打勾、做不通写「卡住了」不自己换做法）。▾ 里指定一位弱模型只做一棒时也是这样；
  - 中途不复核：清单做完后并进终审（`merge`：终审提示里列出所有待复核的棒，终审的人只写一份结论，`applyReviews` 按终审那一棒记的 `targets` 把它记到这几棒上（终审开工后又单独给某一棒写了复核的，以那一份为准）；接力本的「先复核」一节这时也只写这一份。同日大任务实测：终审逐棒读交接、逐棒写 11 份复核，一棒 162.8 万 token；只写一份后 74.1 万。清单写短以后做法会漏细节（那次文章页标题没转义，终审看到了却按清单放过），所以终审提示写明和任务原文对不上时以原文为准）；并过一次还没复核上的，照常单独复核。强模型复核时发现问题直接改好。2026-09-27 对照实测：中等任务里每次中途复核 37–50 万 token，接近 Grok 直接做一遍（54.2 万），所以去掉了「攒 3 棒复核一次」；
  - 弱模型都用不了：开着「等额度」就等最早恢复的弱模型，不然停下（`weakWhy` 写明每一位怎么了）。不换强模型干活、也不复核——强模型干活就是不派活时的全自动；做到哪写在页面上，要复核你来点。
- 换人前先看有没有 AI 正在别的工具里改这个文件夹（几分钟内还有改动）：有就先问你它停没停（网页弹确认，命令行 `--force`），确认了才把它那一棒结账、换人，账上记「你确认过它已经停下」；没确认过的只是账面结束。接力台管不了不守规矩的外部工具，只能不和它同时开工。
- 一个项目同一时间只能有一个调度：`.relay/runs/lock` 只能新建，锁的主人进程没了才算过期。网页和命令行各点一次，后到的会被拒。

## 强和弱

- 默认按模型名判断：Claude（Opus / Sonnet / Fable）、GPT-5 及以上、o3/o4、Gemini Pro 或 3 及以上、Grok 4 及以上算强；其他算弱。可以在「设置」里逐个改。
- 看不出模型的：自动识别加进来的编程工具按弱算；你自己加的、桌面程序用名单里记的（新加时没说强弱也按弱）。
- 名单去重（`detect.ts` 的 `tidyRegistry`，识别完、接力台启动时各看一次）：桌面程序并到同一家的命令行 / 接口上，记成它的 `app`（同一个账号、同一个模型，是一位；▾ 里「打开」用它）；同一个工具、同一个模型的（Claude Code 和 Claude Code 官方账号都是 Opus 5.5）只留派活顺序靠前的那位。同一个模型、不同工具的不并：常常是两份额度（Cursor 里的 Opus 和 Claude Code 的 Opus），额度用完换人时用得上。
- 新识别到的工具按排序先后加（`rank`：桌面版自带的 Claude Code 官方账号排在终端的 Claude Code 前面），同一个工具、同一个模型的只加第一个，所以新装时留下的是写全了版本的那位；你同意用某个密钥（`enableProvider`）之后也整理一次，之前没处挂、单独占着一位的同一家桌面程序（比如 MiMo）记到它名下。
- 删掉的成员记在 `agents.json` 的 `removed`（`h:工具`、`api:接口地址`、`app:桌面程序`），再识别也不加回来；自己再加回来就不算删掉的。
- 看的是**模型**，不是工具：Claude Code 接的是 DeepSeek，它就是弱。
- 自己说的身份不全信：交接里写的工具名会对照自动识别的结果（比如这台电脑的 Claude Code 实际接的是哪个模型）；认不出来的按弱处理，要复核。
- 同一个 claude 命令可能是两位：默认的（`~/.claude/settings.json` 里接到别家模型，比如 DeepSeek）和「Claude Code 官方账号」（harness `claude-official`：`--setting-sources project,local` 跳过用户设置、去掉 `ANTHROPIC_*`，走 claude.ai 登录，默认用这台电脑上最近用过的最新 Opus）。
  - 官方账号优先用 Claude 桌面版自带的那份 Claude Code（`~/Library/Application Support/Claude/claude-code/<版本>/`，跟着桌面版更新）：终端里的 `claude` 旧了也能用最新的 Opus，额度和桌面版是同一份。有桌面版就单列这一位；没有桌面版时，只有默认的接了别家模型才单列。
  - 接力台调用 Claude Code 一律带 `DISABLE_AUTOUPDATER=1`：升不升级由你定。
- DeepSeek Harness（DeepSeek 官方的桌面编程助手，harness `dsh`）：用它自带的 `dsh --profile headless --json`（没装 `dsh` 命令时用桌面程序本身当 Node 跑 app.asar 里的命令行），任务从标准输入给。无界面模式默认走接口密钥，接力台带一个覆盖层（`~/.relay/dsh/headless-patch.yml`），让它用桌面版选的账号和模型（`~/.dsh/profiles/desktop/cordis.patch.yml` 里 agent-default-model 那一段）。安全档 = `DSH_PERMISSION_MODE=workspace-write`，没人应答的审批一律拒绝。
- 以 Claude Code 的会话记录为准（`core/claude-log.ts`，只读模型名、时间、入口、改了哪个文件）：
  - 你自己做的棒结束时：交接文件是 Claude Code 写的，就按记录里的模型认人；认不出是谁时，看上一棒结束以来谁改了项目文件（`.relay/` 下的不算），按最弱的算；算下来是强的、但这段时间有弱模型也改过项目文件，要复核；
  - 复核结论要强模型写的才算数（复核文件是 Claude Code 写的，以记录为准；自己复核自己不算）。不算数的也记下来，接力本里提示强模型参考；
  - 复核是谁写的（`track.ts` 的 `writerOf`、`judgeReviewer`）：按复核文件改动的时间，落在哪一棒从开工到收工的时间里（开工前留 30 秒；收工后不留，收工以后改的不算这一棒）就是哪一棒写的。落不进任何一棒——没有哪一棒在做的时候改的——就认不出来（记 `anon`，不算数；之后 30 秒内有一棒开工了，再认一次，算那一棒的），不能记到最后一棒头上：那一棒早收工了，后来改它的可能是弱模型，也可能是你。写它的那一棒还不知道是谁，先不算，认出来之后再判；复核文件里写的复核人是弱模型，也不算。不算数的复核改不掉原来强模型写的结论（同一份复核文件，算数的只被算数的替换）；
  - 算不算「复核过了」看最近一次算数的复核的结论（`ledger.ts` 的 `reviewStateOf`，读账本时每次重算）：有问题、证据不足、没写清楚都还是待复核；写复核的那一棒被退回了，那次复核作废（撤销退回又算数）；
  - 结论按句子一句一句读（`notes.ts` 的 `verdictOf`）：还有问题、没通过、失败、只修了一部分、推给下一棒算有问题，后面再说「没问题」也盖不过，除非说的是「现在 / 修复后」；没跑测试、「应该没问题」算证据不足；模板里的占位不算写了；
  - 接力台调度的棒：记下工具自己报出来的实际模型（`--model opus` → `claude-opus-5-5`）。
- 派弱模型去复核会直接被拒：它写的复核不算数，白花额度。

## 不变的规矩

1. **事实只认快照**：改了哪些文件、多少行，都由快照比较得出；AI 自己写的交接只作「自述」。
2. **不碰你的 git**：快照在接力台自己的仓库里；不提交、不切分支、不改你的 `.gitignore`。退回只改文件，不动你的提交记录。
3. **账本只追加**：退回也是新记一笔，历史不改写。
4. **退回前先存一张**：退回本身也能撤销。调度、退回和撤销退回、换任务共用一把锁（`ops/lock.ts`，`.relay/runs/lock`，网页和命令行各开一个也一样）：全自动跑到一半不能退回、不能换任务；恢复完拿「退回后」那张和目标比一遍，删不掉、写不回的文件报出来、记进账本（`left`）；动文件前在 `runs/rollback.json` 记一笔，进程中途没了，下次对账时按当时的样子补记（`interrupted`），之后的棒照样作废、照样能撤销。
5. **密钥不落盘、不出网**：配置里只写环境变量名；要用别的工具保存的密钥必须你同意，只在调用时读进内存。群聊、投票发给模型的材料先脱敏；内置小代理（接口成员）读到的文件、命令输出、开工说明发出去之前也一样（`redactSecrets`），抹掉的 `[REDACTED]` 不许原样写回文件；`.env`、私钥、`.npmrc` 这类多半放着密钥的文件（`llm-agent.ts` 的 `SECRET_FILE`），内置小代理不读、搜索时跳过，`.env.example` 这类模板照常。项目的检查命令拿不到像密钥的环境变量（名字带 KEY、TOKEN、SECRET、PASSWORD，各家模型和云的前缀，值像 sk-… 的，`env.ts` 的 `checkEnv`）。这不是隔离：检查命令照样能读写文件、联网，项目里的检查命令要当成项目代码的一部分来看。
6. **宿主凭据隔离**：接力台如果是从某个 AI 工具里启动的，`CLAUDE_*` / `ANTHROPIC_*` 这类会话变量不传给子进程（编程工具、你配的讨论命令都一样，`env.ts` 的 `agentEnv`）。
7. **只写自己的文件**：接力台只写 `.relay/` 下它自己的文件和 `AGENTS.md` / `CLAUDE.md` 里带标记的那一段；AI 正在改的文件（交接）它不去动，免得撞车。例外是退回：任务清单跟着退，只改勾，别的字不动。
8. **读不到就说读不到**：快照比较出错、配置文件坏了、检查没跑起来、账本有读不出来的行，都要报出来、记成「不知道」，不能当成「没改文件」「没配检查」「检查通过」。读不到的棒按要复核算，配置坏了全自动不开工，验收显示「没法验收」（账本坏了写明第几行）。往账本里记之前，上一行写到一半断了就先补一个换行，不让坏的那行把下一条也带坏。
9. **只有验收说了算**：「完成」只有一个出处（`core/acceptance.ts`），各处不各算各的；清单打勾、交接写「全部完成」、模型自述都只是参考。验收对指纹：算出来是通过时，再看文件夹和账本最后记下的快照是否一致（`snap.ts` 的 `changedSince`，git status，不动索引，网页上三秒内复用一次结果）；在接力台之外改过文件，就是「文件夹里有还没记上账的改动」，等对完账算进一棒，旧的检查、终审都不算。终审结束时记下任务的版本（`notes.ts` 的 `taskVersion`：标题、正文、每一步和勾、约定，空行缩进不算），之后任务改过就是「终审之后任务改过」；检查通过记着当时的命令，命令改过就不算。

## 群聊和投票

- **讨论**：选几个 AI，一个接一个发言，后面的看得到前面的。
- **对比**（以前叫「各自」）：同一个问题同时发给每个 AI，互相看不到，回答并排放；避免后说的跟着先说的走。
- **投票**：
  1. 选项可以你来列，也可以让每个 AI 先各出一个方案；
  2. 方案打乱顺序、去掉名字（方案 A、B、C……）发给每个 AI 投票，写理由，不能投自己的；
  3. 一个 AI 一票，不分强弱；你也可以投一票；
  4. 公布票数和理由，再揭晓每个方案是谁出的；平票由你定；
  5. 「采纳」后写进任务的「约定」，之后接力的每一棒都会看到。
- 群聊只说话、不改文件：编程工具用只读模式，接口成员只给看文件的工具。一个 AI 3 分钟一点动静都没有才算卡住，最长说 15 分钟；没说话就结束时写明原因（哪条命令没获准运行、额度用完、工具报的什么错），说法见「结果怎么说」。
- **传文件**：输入框的 +、粘贴、从访达拖进来都走 `/api/upload`：请求体就是文件本身（只收 `application/octet-stream`，别的网站发这种要先预检，过不来），边收边写进项目的 `.relay/uploads/时间-原名`（`files.ts` 的 `saveUpload`，上限 200 MB，那个文件夹自带 `.gitignore`：`*`；快照本来就不收 `.relay/`）。消息最后一段写上反引号括起来的路径，AI 按路径打开（编程工具能看图的就看图）；网页上把这一段画成缩略图和文件小条（`splitFiles`）。缩略图走 `/api/raw`：原样读项目里的文件，带 `sandbox` 的 CSP（带脚本的 svg 在接力台的网址下跑不起来），传上来的文件名字带时间、不会变，浏览器长期缓存。

## 网页

- **三栏**，跟常见的 AI 编程工具一个样子：左边项目和对话，中间对话，右边项目文件。
- **三页**：像 Claude 的 Chat / Code，左上角「接力 / 派活 / 群聊」在同一个网页里切换（`setView`），新内容从切过去的那一边滑进来，开关的滑块滑过去；在接力那一页时群聊来了新回答，「群聊」上有一个小点。
- **一个任务一段对话**：账本里每次「换任务」切一刀（`view.ts` 的 `threadsOf`），这段时间里开始的棒归这一段。
- **群聊分几段**：正在用的是 `.relay/talk.jsonl`，点「新群聊」时改名存档成 `talk-时间.jsonl`（`talk.ts` 的 `archiveTalk`，空的不存）；左边按第一句问话列出来，点开看，在里面说话就先把它换回正在用的（`resumeTalk`，原来正在用的先存档）。存档里的投票只能看。换任务时记下旧任务最后的标题（`prev`），旧对话就用它当标题；更早的账本没记，就从 `做完的任务.md` 里对。
- **一个任务一条线路**：每一棒是一站（编号在小圆圈里，没交接、身份不明的圆圈和线是一串点），终点是验收（`streamItems` 的最后一项：最新的任务看验收，更早的看当时全自动的结果），和别的站一样大的圆圈，通过了是实心的打勾。中间夹着的对话，线从旁边穿过去（`railMarks`）。
- **两边互相点亮、连线**（`wireTo` / `wireLines` / `drawWires`）：小条上停一下，右边它改过的文件标出来，一串点从小条那头的「+」连过去；文件上停一下，改过它的棒四个角出现墨色的裁切线，一串点从文件那头连到这几张小条（露出一半的连到露出来的那一截）；输入框里带上的项目文件停一下，连到文件树里那一行；顶栏「待复核」停一下，待复核的几棒描出来。线从「+」那头一格一格点出去，几根一根接一根（每根晚 32 毫秒）；移开时从终点收回「+」再拿掉（`unwire`，0.2 秒），不是一下子没了。只画看得见的，滚动、换大小时跟着走；窄屏、右栏收起、看着文件页签时不画。
- **只重画变了的地方**：定时刷新拿到的和上次一字不差，就连解析都不做（`api` 的 `same`）；变了，每一块再按内容算签名，签名没变就不动；对话流按 key 对齐，只换变了的小条。所以定时刷新时，输入框里的字、展开的小条、滚动位置都不会被打断。一棒变了（交接写完了、有了复核），它展开的全文也重新取。
- **动画都接得上，中间都有过渡**：动的只有 transform 和 opacity。新来的一项浮上来（一批一起来的一个接一个），弹窗、菜单、提示、搜索退场时先淡出（`leave`），分段按钮的选中块滑过去，文件树展开收起时各行从原位置滑到新位置（`rowTops` / `glide`），换浅色深色整页淡入淡出。2026-09-29 把剩下「一下子就换好」的地方都补上了过渡：
  - 整块重画的（顶栏、空白页顶上、页签）用 `morph`：重画前记下每一项（`data-k`）在哪、写的什么，重画后还在的从原位置滑过去，字变了的淡一下换上，新来的晚 60 毫秒淡进来。「全自动」变「停止」、多了「待复核」、侧栏收起后顶栏多出一颗按钮，旁边的字都是滑过去让位的；
  - 对话流里一棒变了（`syncList` 的 `settle`）：换上新画的小条后，状态、那一句、底下一行里变了的部分淡一下；清单里 AI 刚打上的勾也画一笔；拿掉的一项淡出；
  - 左栏重画：新来的对话淡进来，右边的时间、「待复核几棒」变了的淡一下，不整列闪；
  - 换对话、新任务、换一段群聊（`turnPage`）：左边的选中马上跟过去，中间旧的先淡出 0.1 秒，新的一项项升上来；
  - 设置：左边选中的那一块滑过去（和分段按钮同一个弹簧），换页时旧的一页淡出 0.11 秒、新的一行接一行升上来；开关、分段、数字原地改好再存，存的时候不重画这一页（以前一存就整页重画，开关、滑块是跳过去的，每一行还重放一次升起）；数字从上下翻过来；
  - 藏起来的（「新消息」、连不上、配置坏了）先淡出再藏（`show`）；约定、每一票、改动里的文件这些折叠段落长开、缩回（`::details-content`，浏览器不支持就直接开合）；
  - 打勾：方框落一下，勾一笔画出来，步骤的删除线淡进来；发出去之后占位字淡进来，发送键的箭头从底下补上。
  系统设了「减少动态效果」就全部关掉。
- **按下有反馈**：按钮、图标按钮按下缩一点、松开弹回；一整行能点的（对话、文件、菜单项、顶栏小按钮、投票的方案）按下底色深一档。不能点的东西不加悬停效果（代码行的悬停底色去掉了）。
- **两种语言**（2026-09-29）：英文名叫 RelayDesk（「接力台」直译；RelayCrew 在 GitHub 上有做同一件事的同名项目，没用），npm 包名 `relaydesk`（原来的 `agent-relay` 在 npm 上被别人占了），命令还是 `relay`。左下角设置旁边一颗「EN / 中」，写的是另一种语言的名字，点一下就换；「设置 → 通用 → 语言」、⌘K 里搜 English 也行。第一次打开按浏览器的语言（中文浏览器是中文，别的是英文），换过就记在本机浏览器里。做法：`app.js` 里界面上的字照常写中文，套一层 `T\`…\``（`i18n.js`）；中文原样拼，英文查 `EN` 表（`{}` 是原文里 `${…}` 的位置，要按数量变单复数的写成函数；同一个词在别处英文不一样时用 `L(词, 上下文)`）。表里有没有漏的由测试查（`test/i18n.test.ts` 把 `app.js` 里每个 `T\`…\`` 都找出来对）。接力台后台送来的字（状态、复核结论、验收、恢复时间、出错原因、成员的「官方账号 / 命令行 / 接口」）套 `tr(…)`：先整句对照（`SRV_WORD`），再按句式换（`SRV`），用「，」「；」连起来的一句句换，都不认识就原样；AI 写的交接、人写的任务不翻。换语言要重新载入一次（界面上的字都是画的时候取的，常量也是载入时算的）：先记下正在看的（哪段对话、打开的页签、展开的卡片、滚到哪、设置开在哪一页）和输入框里的字，整页 0.2 秒淡出，载入、摆回原样后 0.32 秒淡进来，纸色垫在 `html` 上，中间不闪白。网页的语言也存进运行设置（`auto.json` 的 `lang`）：英文时给 AI 的话后面加一段（`auto-settings.ts` 的 `langNote`），请它用英文写交接、复核和回答，接力台要认的小节标题、状态、结论选项、文件名照原样写中文。接力规矩、接力本、交接模板本身还是中文（见「已知限制」）。
- **屏幕多大都能用**（2026-09-29）：窄于 860px（手机、竖着的平板）两边的栏变成抽屉；860～1180px 放不下三栏时右栏自己收起、宽回来自己打开（`mqMid`、`fitRight`，和点按钮一样滑、扫一道点），这时点开右栏只是临时的，不改你记下的收起 / 打开；宽于 1800px、2300px 时对话、输入框、空白页跟着放宽，不在正中间缩成一条。小条上地方不够时先缩时间和用量（`flex-shrink` 1000），名字最后缩。收在屏幕外的抽屉不撑出横向滚动（`html` 的 `overflow: clip`）。实测 375、768、1024、1280、1920、2560 宽都没有横向滚动、控制台没有报错。

- **原生 Windows 版**（2026-09-29）：不用 WSL。调度要起的程序都经 `proc.ts`：shell 命令（检查命令、自定义讨论命令、打开命令）Mac/Linux 交给 `sh -c`，Windows 交给 `cmd.exe /d /s /c`（`shellArgv`，整条原样传）；工具按 PATHEXT 找（`which`：`codex` 找到 `codex.cmd`，npm 放在旁边的无扩展名 sh 脚本不算，Windows 上不看「可执行」位）；npm 装的 `.cmd` 只是转手用 node 跑包里的 `.js`，读出那个文件直接跑（`npmShimTarget`、`resolveExec`），因为 `.cmd` 只能经 cmd.exe 起，多行的提示词过不去，新版 Node 也不让直接起 `.cmd`；认不出的 `.cmd` / `.bat` 才经 cmd.exe。Windows 没有进程组：`spawnTool` 在 Mac/Linux 上照旧让工具自成一组，Windows 上不分组、不弹黑窗口，结束时 `killTree` 用 `taskkill /T /F` 连子进程一起（命令行程序收不到「请退出」，只能强制）；上次关掉时留下的工具，按进程号查它现在的命令行里有没有这个工具的名字再结束（`go.ts` 的 `winToolAlive`）。PATH 用系统的分隔符，Windows 上补 `%APPDATA%\npm`、`~\.local\bin`，继承来的 `Path` 先去掉再写 `PATH`（不然子进程里有两个）。命令模板里的路径按 cmd.exe 的双引号转义，分词时反斜杠当路径。`npm run build` 改成 Node 写的 `scripts/build.js`（原来的 rm / cp / mv Windows 上没有）。安装：`install-windows.cmd` → `scripts/windows/install.ps1`（带 BOM 的 UTF-8，不然 PowerShell 5 把中文读成乱码）：没有 Node、Git 用 winget 装，装依赖、编译，开始菜单和「启动」文件夹里各放一个「接力台」快捷方式，指向 `wscript` + `relaydesk.vbs`（UTF-16 存，不弹黑窗口），它跑 `launch.js`：没在运行就起一个看守进程（`--keep`，对应 Mac 上的小程序：意外退出、编译出新版就重新拉起，网页上点了「关闭」就不再拉起，一分钟退出 5 次就不拉了），再打开网页；出错时弹窗并用记事本打开 `~/.relay/ui.log`。图标 `scripts/windows/icon.ico` 从 `icon.png` 裁掉阴影做的。测试按 Windows 的规矩算（`test/windows.test.ts`），`launch.js` 在 Mac 上实跑过启动、被杀后拉起、关闭；没在真机上跑过。
- **会改结果的操作先问一句**：退回、跳过复核都先确认，做完的提示里带「撤销」。
- **只认本机页面的请求**：Host 只认本机地址和本端口；带了别的网站 Origin 的、浏览器标明从别的网站来的（`Sec-Fetch-Site: cross-site / same-site`）一律 403；POST 必须是 JSON。GET 不在没接入的文件夹里写东西（看改动要先接入）。

- **极简**：平时只露一句话，细节悬停或点开再看。小条底下不列文件名（合成「3 个文件 +12 −3」，悬停看清单、点开看改动），要注意的（待复核、出错、检查没过）才加深。顶栏只有「项目 / 任务几」、几句淡字（谁在干活、待复核几棒、清单几步）和一个主按钮「全自动」，▾ 里选人只做一棒。
- **神性的骨架，人性的手迹**：骨架是规整的三栏、细线、线路和编号；中间是点阵纸，两边的纸面带一点颗粒，小条像钉在纸上，输入框、菜单、搜索是半透明的磨砂纸。空闲时中间只有一个小标题、要人看的一行（有待复核的棒时）和输入框，不放大块装饰。
- **瑞士版式、连续的东西拆成一格一格的点**（2026-09-28 按两张海报加的细节：一张是一笔弯线拆成一排排椭圆点，一张是网点照片压在细线格子上、角上有「+」）：
  - 切页（`paperSweep`）：从切过去的那一边扫一道，往右边的页切就从左往右扫，往左切就从右往左扫，新内容也顺着同一个方向滑进来。扫过去的是这一页的走向（接力一笔、派活分三股、群聊三股汇成一股）和笔画；前沿先快后慢（t80 约 0.5），扫到哪儿纸就从旧的换成新的（交界 60px 两种叠着渐变），约 0.9 秒。浅色主题里那一道的深浅乘 1.35（`--sweep`，浅底上的深墨显得淡；9-29 用户说浅色的不够明显），深色不乘；最深封顶 0.6。
  - 收起、打开侧栏：栏宽 0.42 秒、抽屉曲线 `--drawer`；里面的内容整块朝屏幕边滑出去 18px、淡出（左栏的内容贴右边放，收窄时是往左滑走，不是被一刀切掉），打开时晚 0.08 秒从边上滑回来、淡进来。挨着对话的那条边化成一道点跟着边走（`sideSweep`：42px 宽，越靠边越密越大，分三档；收起时跟着边收走，打开时边停稳前散掉）。画布放在这一栏里面、贴着内沿，栏收窄就一起被裁掉——2026-09-29 以前画布盖在整个三栏上、宽度是栏原来的宽度，栏收起后点还留在对话的空白处，用户指出后改的。收放时顶栏替它留的那颗按钮淡进来，旁边的字滑过去让位（`morph`）。
  - 切换的那一下（2026-09-28 借一段滑块录屏里像素一格格铺开的动法，换成我们自己的点和墨色）：分段按钮换一块时，滑块身后留一串 4px 一格的细点，滑块经过哪儿哪儿亮、离得越远越小，停下来就散完（`segWake`，页面开关、群聊的讨论 / 对比 / 投票、成员强弱都是）；开关打开时墨点跟着圆钮一颗颗铺满、随后换成底色，关上时从圆钮离开的那头一颗颗散掉（`switchSpecks`）。点都垫在底色之上、滑块和字之下（`underlay`），画完就拿掉。
  - 纸（`app.js` 的「纸」一节，一张画布）：三页三种纸，每格一个小记号（2026-09-28 借一段网站录屏的意思：同一只蝴蝶轮流用竖排字、网点、剪纸来画，换的是材料）：接力是点（20px 一格），派活是一竖、群聊是一横（18px 一格，比点阵纸密一点，记号大小不变）；点、竖、横也是写字最基本的三笔。试过把派活、群聊改成 10px 一格、每 4 列长一点、横纹排成字的样子，用户要的「密」只是空隙小一点，已退回。群聊页每段回答、每张投票底下（四周多留 8～10px）不画横纹，字不叠在纹上（`paperHoles`，滚动时一帧重画一次，约 1.2 毫秒）；别的页不挖。

  - 对准标记：顶栏底线碰到左右分栏线的地方各一个细「+」。
  - 裁切角：小条悬停时四个角淡淡围过来，停在文件上点亮的那几张是墨色的；输入框打字时围过来，拖文件进来时是墨色的。
  - 点线：连线、身份不明的线路和圆圈、交接单的格线都是一串点。
  - 一格一格动的：新来的一棒像网点印刷，先是小点、点长大连成一片；进行中的那一站下面一个点往下跳；等待的转圈是一圈点、缺口一格一格走；投票进度是小方格，投一票填一格；顶栏的数字变了从下面翻上来。
- **每样东西都该在那儿**：从一个没参与过的人的眼光看，出现的东西都不突兀：没有大块红色、没有空白处的大标签；按钮和输入框只写名字（「接入」「消息」「要做什么」），不写教人怎么用的句子。
- **颜色**：黑白灰，外加一颗小红点。大块面只用白和灰；红点只放在要人管的字前面（待复核、验收没过、出错、连不上），不单独放大。深色是「暗房」：纸是黑的，红点还是那颗红点。

## 动效

按动效技能（onetake）的做法定的，数字是实测：

- **只动 transform 和 opacity**；系统设了「减少动态效果」就全部关掉。例外都只在一小块上：纸画在一张画布上，按钮里的细点画在临时的小画布上（画完就拿掉），网点进场动的是遮罩里点的半径，裁切角动的是伪元素的位置。
- **曲线按用途分**，不再一条用到底（t80 = 走完八成路程用掉的时间占比，越小越「一下就到」）：进场、升起 `--ease`（t80 .31）；弹出、从按钮长出来 `--snap`（expoOut，t80 .23）；退场 `--exit`，加速离开（t80 .87），也比进场短；手拖的切换（分段滑块、按下松开、列表重排、两页切换）`--spring`，是 SwiftUI 的 Spring(duration .35, bounce .15) 做成 CSS 的 `linear()`：0.49 秒停稳，t80 .29，最多冲过 0.6%；落定（打勾、验收通过、成员叠放散开）`--pop`，Spring(.45, bounce .22)，最多冲过 2%；侧栏收放 `--drawer`（像抽屉，起步利落、收尾很长，t80 .26）。不支持 `linear()` 的浏览器退回贝塞尔。JS 里的动画用同一套（`EASE`）。
- **按下的东西变成结果**：菜单从按钮那个角弹出；弹窗从按下的按钮（或菜单里那一项）长出来，关掉时缩回去（`sheet()`、`toward()`）。
- **一批一起进场不像节拍器**：第 i 个晚 110 ×（1 − 0.82^i）毫秒，前几个拉开，后面的挤在一起到（`stagger`）。
- **静得下来**：只有在干活、在加载、正在输入时才有循环的动画，空闲时画面是静的；纸只在指针划过、切页的那一下逐帧画，停了就不再排下一帧。
- **背景的动效只有一套**：输入框周围、指针划过、切页扫一道，都只是给纸上每个格点一个 0～1 的深浅，取最大的，分 4 档，一档一条路径一起画。以后再加背景效果也是往这个深浅里加一项，不另叠一层画布、遮罩或元素，叠几样开销都一样。
- 实测（无界面 Chrome，60Hz）：弹窗开关 3 次、两页来回切换 2 次，397 帧，没有长任务，最长一帧 16.8 毫秒。
- 纸实测（2 倍屏，1440 宽）：整张画一次约 1.2 毫秒，指针划过时只画经过的一块约 0.1 毫秒；划动时最长一帧 9 毫秒，来回切页 4 次最长一帧 17 毫秒，都没有长任务；停下后不再排帧。分段按钮的细点约 0.5 秒拿掉，开关约 0.3 秒。在小条之间悬停（连线、裁切角）最长一帧 9 毫秒。
- 侧栏收放（2026-09-29，120Hz 屏）：左右各收放两次，每次约 80 帧，最长一帧 10.3 毫秒，没有超过 20 毫秒的帧。
- 按 /动效 的方法实测一遍全部交互（2026-09-28，录屏 20 秒，用它的 analyze_ref.py 量）：87% 的画面完全静止，最长一段静止 9.7 秒；9 处循环动画都只在进行中（在干活、加载、投票、上传、输入）才转；特效里没有随机数，同一处每次画出来一样。扫点的前沿原来是匀速（t80 0.8～1.0，和先快后慢滑进来的内容对不上，看着在爬），改成先快后慢后，动作的中位 t80 从 1.0 降到 0.6；网点进场改用进场曲线 `--ease`。最快的一帧来自侧栏收起时中间一栏整体挪位（原有的布局动画，60 帧屏上每帧约 98 像素，一闪而过）。

## 结果怎么说

群聊、投票、每一棒、全自动、验收、网页提示、命令行，说「成了」「没成」「为什么」都用同一套说法。原因的词表在 `core/cause.ts`，网页的失败提示都走 `app.js` 的 `fail`。

- **一句话**：主语在前，结果紧跟，原因放在全角冒号后面，几条原因用「；」隔开，不加句号。
- **只写事实**：发生了什么、为什么。不写建议和下一步，不用「你」「吧」「先……再……」「看看」；怎么处理写在 README 的「常见问题」。
- **主语**：成员写模型名（GPT-6 Sol）；一棒写「第 N 棒（模型名）」；整体写「全自动」「验收」「检查」「终审」。
- **原话**：工具和模型自己说的话一律放在「原话：」后面，照录，只去掉句末的句号。
- **旧记录不回头改**：群聊、账本里已经存下的话保持原样。

成对的结果：

| 场景 | 成了 | 没成 |
|---|---|---|
| 群聊发言 | 直接显示回答 | GPT-6 Sol 没有回答：原因 |
| 投票 | 显示方案和票 | 弃权（原因）；投票没开始：只有 1 个方案 |
| 一棒 | 第 3 棒（DeepSeek Flash）已交接：摘要；待复核 | 第 3 棒（X）出错 / 额度用完 / 已停止 / 没交接：原因 |
| 全自动 | 验收通过：清单 5/5 全部打勾，GPT-6 Sol 终审过了，检查通过 | 全自动停止：原因；全自动已停止：改到一半的内容还在文件夹里；全自动出错：原因 |
| 验收 | 验收通过：…… | 验收没过：……；没法验收：…… |
| 检查 | 检查通过 | 检查没过（第 N 棒之后）；检查没跑成 |
| 网页操作 | 已保存、已开始全自动、已停止 | 没能保存：原因 |
| 成员 | 列在「能派活」里 | GLM-5.3 不能派活：没登录 |

原因的说法：

| 情况 | 说法 |
|---|---|
| 一段时间一点输出都没有 | 3 分钟没有输出，已停止 |
| 超过总时长 | 超过 15 分钟，已停止 |
| 额度用完、余额不足 | 额度用完，15:00 恢复，原话：…… |
| 要人点头的操作被拒 | 「textutil ……」没获准运行 |
| 出错退出 | 退出码 1，原话：……（原话取工具最后报的那条错） |
| 出错退出，原话是连接类的错（超时、连接被断、反复重连） | 连不上服务器，原话：…… |
| 结束了、一句没说 | 没有输出（退出码 0） |
| 认得的报错（`explainFailure`） | ZCode 命令行没有默认模型；没登录或登录过期 |
| 回的是调用工具的原文 | 回的是调用工具的原文 |

状态词：进行中、已交接、没交接、额度用完、出错、已停止。复核和终审的结论：没问题、有问题，已修好、改坏了，已退回、有问题，还没修、证据不足。

## 已知限制

- 外部编程工具（Claude Code、Codex、Cursor……）自己读文件、联网、跑命令，按它们自己的权限档；接力台的脱敏只管它自己发出去的（群聊、投票、内置小代理）。给它们的环境里有用户配的密钥（它们自己要用），只去掉宿主注入的会话变量。
- 检查命令没有隔离，只去掉像密钥的环境变量。macOS 上真隔离要 `sandbox-exec`（苹果已不推荐），成本高，首版不做。
- 真实工具实测过的异常流程（2026-09-29，`试跑记录/异常流程实测`，DeepSeek Harness、Codex、智谱接口）：叫停后 2 秒内工具进程退出、之后 20 秒文件不再变；断网（给子进程配一个不存在的代理）时 Codex 会每分钟报一次「Reconnecting... waiting for network」永远不退出，原来要等整棒超时，改成连着 3 分钟只剩连不上服务器就停（`runner.ts` 的 `offlineMs`，190 秒停下），接口成员 9 秒报「连不上」；kill -9 接力台后 DeepSeek 的 dsh 1 秒内自己退出，Codex 会在后台再活十几秒以上，下次开工按整组结束（`go.ts` 的 `toolGroup`，5 秒内结束）；退回、撤销后文件、清单的勾、账本、验收都对得上。额度用完没法真的触发（要烧完一整份额度），用注入的等额度记录测：指名派活原来照派不误，改成先拦下（`--force` 照派）。实测程度按工具记在 `harness.ts` 的 `tested`，网页成员名单上写「部分实测」「没实测」。
- 只在 macOS 上正式用过；Linux 只在 CI 里跑过测试；Windows 版没在真机上跑过（选文件夹、复制、调度各家命令行工具、安装和启动器都按 Windows 的做法写了，测试按 Windows 的规矩算过）。
- 英文版只到网页和给 AI 的一句「用英文写」：接力规矩（`AGENTS.md` / `CLAUDE.md` 里那一段）、接力本、交接模板、`.relay/` 里的文件名还是中文，接力台读交接时认的也是中文的小节标题和结论。全换成英文要改解析，并且要拿真实工具重新验一遍。`scripts/e2e.py`（浏览器真实点击）要 playwright，不在 `npm test` 里。

## 从 1.x 留下来的

- 自动识别编程工具和模型接口、各家无人值守的调用参数、输出解析、网络抖动重试。
- 内置小代理（让只有接口的模型也能改文件）、思考内容回传。
- 强 / 弱标记、「弱模型的活要先审」的想法、检查命令、不许改的文件。
- 讨论（群聊的底子）、本机网页的安全检查、桌面小程序。

去掉的：隔离副本、开始任务 / 合回 / 同步 / 收进 / 放弃、会话锁、审计（便宜模型读改动写摘要；现在由强模型直接看真实改动复核）。旧版的代码在 `auto-1.1` 分支。

## 测试

`npm test` = 编译 + `node --test dist/test/*.test.js`。假的 claude / codex / dsh 程序（参数和输出格式跟真的一样）和假的模型接口，覆盖快照、账本、接力本、交接识别、调度、额度用完换人、复核、退回、群聊投票、网页接口。`test/accept.test.ts`、`test/guard.test.ts` 是 2026-09-25 审查的反例（复核结论的写法、验收、快照读不出来、配置坏了、退回的任务清单、换人确认、调度锁、内置小代理的路径、网页切换项目的旧响应），改这些地方要先让它们照样过。假工具测试过了不等于真实工具验收过了。

网页的真实点击：`python3 scripts/e2e.py`（起一个假家目录的接力台，用浏览器点切页、划过纸面、收起打开侧栏（点只在侧栏里面）、设置（切页时页签滑块跟过去）、窗口变窄右栏自己收起、一键换成英文再换回来（英文表不漏、接力台记下语言），控制台不许报错；共 19 项）。

测试环境变量：`RELAY_HOME`（数据目录）、`RELAY_LOGIN_PATH=off`、`RELAY_SCAN_APPS=off`、`RELAY_AUTODETECT=off`、`RELAY_TERMINAL=off`、`RELAY_CLIPBOARD=off`、`RELAY_RETRY_MS`（网络抖动后隔多久再试）。

可以调的时间：`RELAY_QUIET_MS`（有改动、没交接，多久没动静算被打断，默认 20 分钟）、`RELAY_COOLDOWN_MS`（额度用完但认不出恢复时间时先歇多久，默认 1 小时）、`RELAY_WATCH_DEBOUNCE_MS`（文件有变化后等多久再对账，默认 4 秒）、`RELAY_WATCH_TICK_MS`（没有变化也隔多久对一次账，默认 1 分钟）。
