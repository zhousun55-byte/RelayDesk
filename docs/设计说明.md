# 接力台设计说明（2.0）

给以后改代码的人（和 AI）看的。用户手册见 [README](../README.md)。

## 为什么有接力台

一个人手上有好几个 AI：Claude、Codex（GPT）、Cursor、ZCode、MiMo、DeepSeek……每个都有额度。
常见的一天是这样的：

1. 先用 Claude 做一件事，做到一半额度用完了；
2. 转头在**同一个文件夹**里打开 Codex 接着做，又用完了；
3. 只剩 DeepSeek 能用。它便宜，但明显弱一些，怕它把代码改坏。

接力台要做到：**不管换哪个模型接着做，都不影响项目的进度、完成度和正确率。**

- **进度不丢**：谁一开工就知道任务是什么、做到哪了、上一棒留了什么话、哪里还没做完。
- **改动都有账**：每一棒改了哪些文件、自己说做了什么，都记下来；就算它额度用完被打断、没来得及留话，接力台也替它记一笔。
- **弱模型的活有人复核**：弱模型（比如 DeepSeek）做的每一棒自动标「待复核」。强模型（Claude、GPT……）额度恢复后，先对照它的交接把真实改动核一遍：说做了的是不是真做了、有没有改错，错的直接修好，再接着往下做。
- **改坏了能退回**：每一棒前后都有快照，可以退回到任何一棒之前。
- **不用动手**：可以自己在各个 AI 工具里接着干（接力台只管记账和提醒），也可以让接力台替你调度——额度用完自动换下一位，强模型额度恢复后自动去复核。

另外一个想法是**群聊**：既然有这么多 AI，就把它们拉进一个群，对同一件事各出主意；再加上**投票**，每个 AI 一票、方案匿名，弱模型的好想法也不会因为它弱被忽略。

## 1.x 哪里偏了

1.x 做成了「开任务 → 在项目外的隔离副本里干活 → 另一个 AI 审查 → 合回」的流水线。问题是：

- 你平时是**直接在项目文件夹里**打开 Codex、Claude 接着干的；隔离副本在别的地方，你手动换人时它们根本看不到。
- 每件事都要先在接力台里「开始任务」、最后「合回」，多出来很多点点点。
- 它关心的是「这一件事审完合回」，而你关心的是「换人之后能不能接得上、弱模型的活有没有人把关」。

2.0 改成：**就在项目文件夹里干活**，接力台在旁边记账、提醒、调度。

## 核心概念

| 叫法 | 是什么 |
|---|---|
| 接入 | 让一个文件夹开始接力：建 `.relay/`，在 `AGENTS.md` / `CLAUDE.md` 里加一段「接力规矩」（各家 AI 工具开工时都会读） |
| 接力本 | `.relay/接力本.md`，接力台生成的「开工必读」：任务、进度、上一棒的话、待复核、强弱名单、这一棒要做什么 |
| 任务 | `.relay/任务.md`：当前任务、进度清单、约定。AI 和你都可以改 |
| 棒 | 一个 AI 连续干的一段。第 1 棒、第 2 棒…… |
| 交接 | `.relay/交接/*.md`：每一棒结束时（最好边做边写）AI 自己写的话：做了什么、没做完的、不确定的地方、下一步 |
| 快照 | 整个文件夹的存档。存在 `.relay/snapshots/`（接力台自己的 git 仓库，**不碰你自己的 git**），每一棒前后各一张 |
| 待复核 | 弱模型做的、或者不知道是谁做的（没留交接）的棒 |
| 复核 | 强模型对照交接看真实改动，把结论写进 `.relay/复核/第N棒.md`。「结论」一行只写五种之一：没问题 / 有问题，已修好 / 改坏了，已退回 / 有问题，还没修 / 证据不足。前三种才算复核过 |
| 验收 | 这件事能不能算做完了（`core/acceptance.ts`，全自动收工、网页顶部、接力本、`relay status` 都只看它）：清单全打勾、弱模型的棒都复核通过、终审通过、检查通过、证据都读得到 |
| 成员 | 这台电脑上认出来的 AI：编程工具（Claude Code、Codex、Cursor Agent、ZCode……）和模型接口（DeepSeek、MiMo……），每个标「强」或「弱」 |

## 两种接着做的方式

### 自己接着做（在各家工具里）

接入后，什么都不用点：直接在项目文件夹里打开任意 AI 工具说「接着做」。

- `AGENTS.md`（Codex、Cursor、ZCode、MiMo 等都会读）和 `CLAUDE.md`（Claude Code 读）里有一段接力规矩，由接力台维护，前后有标记，不动你自己写的内容。
- 规矩只有几条：开工先读接力本；强模型先复核待复核的棒；边做边在任务里打勾；收工前写交接。
- 接力台开着的时候，它在后台盯着这个文件夹：文件一有变化就存快照；发现新的交接就把这一棒记上账；一段改动之后 20 分钟没动静又没人交接，就当它被打断了，替它记一笔（标待复核）。

### 让接力台调度

网页上点「接着做」（或者换人），或者打开「全自动」：

- 接力台用这个工具的无人值守模式在**项目文件夹里**干一棒（Claude Code `-p`、Codex `exec`、Cursor Agent `-p`……；只有接口的模型用内置小代理）。
- 前后各存一张快照；它没写交接就用它最后说的话代写一份；跑检查命令；弱模型的棒标待复核。
- **全自动**：一直接着做，直到验收通过（不只是清单打勾）。
  - 额度用完（认得各家的提示），就记下什么时候恢复，换下一位；
  - 有待复核、又有强模型能用，先派强模型复核；复核两次还没过（结论是有问题、证据不足、没写清楚），停下交给你；
  - 全都没额度了就等，等到最早恢复的那一位；
  - 清单打完后请强模型把整件事从头到尾过一遍（终审，最好换一位没干过活的）。终审算数要：交接成功、实际跑的是强模型、结论是「没问题」或「有问题，已修好」、终审之后没人再改文件。两次都不算数就停下；开着终审却请不到强模型、又不等，也停下，不会跳过终审说「完成」；
  - 配了检查命令：最后一次改动之后没跑过检查就补跑一次；检查没过就停下。
- 换人前先看有没有 AI 正在别的工具里改这个文件夹（几分钟内还有改动）：有就先问你它停没停（网页弹确认，命令行 `--force`），确认了才把它那一棒结账、换人，账上记「你确认过它已经停下」；没确认过的只是账面结束。接力台管不了不守规矩的外部工具，只能不和它同时开工。
- 一个项目同一时间只能有一个调度：`.relay/runs/lock` 只能新建，锁的主人进程没了才算过期。网页和命令行各点一次，后到的会被拒。

## 强和弱

- 默认按模型名判断：Claude（Opus / Sonnet）、GPT-5 及以上、o3/o4、Gemini Pro、Grok 4 及以上算强；其他算弱。可以在「设置」里逐个改。
- 看的是**模型**，不是工具：Claude Code 接的是 DeepSeek，它就是弱。
- 自己说的身份不全信：交接里写的工具名会对照自动识别的结果（比如这台电脑的 Claude Code 实际接的是哪个模型）；认不出来的按弱处理，要复核。
- 同一个 claude 命令可能是两位：默认的（`~/.claude/settings.json` 里接到别家模型，比如 DeepSeek）和「Claude Code 官方账号」（harness `claude-official`：`--setting-sources project,local` 跳过用户设置、去掉 `ANTHROPIC_*`，走 claude.ai 登录，默认用这台电脑上最近用过的最新 Opus）。
  - 官方账号优先用 Claude 桌面版自带的那份 Claude Code（`~/Library/Application Support/Claude/claude-code/<版本>/`，跟着桌面版更新）：终端里的 `claude` 旧了也能用最新的 Opus，额度和桌面版是同一份。有桌面版就单列这一位；没有桌面版时，只有默认的接了别家模型才单列。
  - 接力台调用 Claude Code 一律带 `DISABLE_AUTOUPDATER=1`：升不升级由你定。
- DeepSeek Harness（DeepSeek 官方的桌面编程助手，harness `dsh`）：用它自带的 `dsh --profile headless --json`（没装 `dsh` 命令时用桌面程序本身当 Node 跑 app.asar 里的命令行），任务从标准输入给。无界面模式默认走接口密钥，接力台带一个覆盖层（`~/.relay/dsh/headless-patch.yml`），让它用桌面版选的账号和模型（`~/.dsh/profiles/desktop/cordis.patch.yml` 里 agent-default-model 那一段）。安全档 = `DSH_PERMISSION_MODE=workspace-write`，没人应答的审批一律拒绝。
- 以 Claude Code 的会话记录为准（`core/claude-log.ts`，只读模型名、时间、入口、改了哪个文件）：
  - 你自己做的棒结束时：交接文件是 Claude Code 写的，就按记录里的模型认人；认不出是谁时，看上一棒结束以来谁改了项目文件（`.relay/` 下的不算），按最弱的算；算下来是强的、但这段时间有弱模型也改过项目文件，要复核；
  - 复核结论要强模型写的才算数（复核文件是 Claude Code 写的，以记录为准；自己复核自己不算）。不算数的也记下来，接力本里提示强模型参考；
  - 算不算「复核过了」看最近一次算数的复核的结论（`ledger.ts` 的 `reviewStateOf`，读账本时每次重算）：有问题、证据不足、没写清楚都还是待复核；写复核的那一棒被退回了，那次复核作废（撤销退回又算数）；
  - 结论按句子一句一句读（`notes.ts` 的 `verdictOf`）：还有问题、没通过、失败、只修了一部分、推给下一棒算有问题，后面再说「没问题」也盖不过，除非说的是「现在 / 修复后」；没跑测试、「应该没问题」算证据不足；模板里的占位不算写了；
  - 接力台调度的棒：记下工具自己报出来的实际模型（`--model opus` → `claude-opus-5-5`）。
- 派弱模型去复核会直接被拒：它写的复核不算数，白花额度。

## 不变的规矩

1. **事实只认快照**：改了哪些文件、多少行，都由快照比较得出；AI 自己写的交接只作「自述」。
2. **不碰你的 git**：快照在接力台自己的仓库里；不提交、不切分支、不改你的 `.gitignore`。退回只改文件，不动你的提交记录。
3. **账本只追加**：退回也是新记一笔，历史不改写。
4. **退回前先存一张**：退回本身也能撤销。
5. **密钥不落盘**：配置里只写环境变量名；要用别的工具保存的密钥必须你同意，只在调用时读进内存。群聊、投票发给模型的材料先脱敏。
6. **宿主凭据隔离**：接力台如果是从某个 AI 工具里启动的，`CLAUDE_*` / `ANTHROPIC_*` 这类会话变量不传给子进程。
7. **只写自己的文件**：接力台只写 `.relay/` 下它自己的文件和 `AGENTS.md` / `CLAUDE.md` 里带标记的那一段；AI 正在改的文件（交接）它不去动，免得撞车。例外是退回：任务清单跟着退，只改勾，别的字不动。
8. **读不到就说读不到**：快照比较出错、配置文件坏了、检查没跑起来，都要报出来、记成「不知道」，不能当成「没改文件」「没配检查」「检查通过」。读不到的棒按要复核算，配置坏了全自动不开工，验收显示「没法验收」。
9. **只有验收说了算**：「完成」只有一个出处（`core/acceptance.ts`），各处不各算各的；清单打勾、交接写「全部完成」、模型自述都只是参考。

## 群聊和投票

- **讨论**：选几个 AI，一个接一个发言，后面的看得到前面的。
- **各自**：同一个问题同时发给每个 AI，互相看不到，避免后说的跟着先说的走。
- **投票**：
  1. 选项可以你来列，也可以让每个 AI 先各出一个方案；
  2. 方案打乱顺序、去掉名字（方案 A、B、C……）发给每个 AI 投票，写理由，不能投自己的；
  3. 一个 AI 一票，不分强弱；你也可以投一票；
  4. 公布票数和理由，再揭晓每个方案是谁出的；平票由你定；
  5. 「采纳」后写进任务的「约定」，之后接力的每一棒都会看到。
- 群聊只说话、不改文件（编程工具用只读模式）。

## 网页

- **三栏**，跟常见的 AI 编程工具一个样子：左边项目和对话，中间对话，右边项目文件。
- **一个任务一段对话**：账本里每次「换任务」切一刀（`view.ts` 的 `threadsOf`），这段时间里开始的棒、说的话、投的票都归这一段。换任务时记下旧任务最后的标题（`prev`），旧对话就用它当标题；更早的账本没记，就从 `做完的任务.md` 里对。
- **两边互相点亮**：卡片上停一下，右边它改过的文件标出来；文件上停一下，改过它的棒描出来。
- **只重画变了的地方**：每一块都按内容算一个签名，签名没变就不动；对话流按 key 对齐，只换变了的卡片。所以定时刷新时，输入框里的字、展开的卡片、滚动位置都不会被打断。
- **文案**：按钮只写动作（「接着做」「复核」「退回到这之前」），用中立的说法，不写「你 / 我」；不在界面上教怎么用；不需要改、也不需要解释的内容不显示（比如规矩是最新的就不提）。
- **颜色**：只有黑、白、灰。大块面只用白和灰，黑色留给按钮、标签、每个 AI 的方块这些小地方；每个 AI 一种深浅（加两个字母），在卡片、接力条、文件树里都一样。

## 从 1.x 留下来的

- 自动识别编程工具和模型接口、各家无人值守的调用参数、输出解析、网络抖动重试。
- 内置小代理（让只有接口的模型也能改文件）、思考内容回传。
- 强 / 弱标记、「弱模型的活要先审」的想法、检查命令、不许改的文件。
- 讨论（群聊的底子）、本机网页的安全检查、桌面小程序。

去掉的：隔离副本、开始任务 / 合回 / 同步 / 收进 / 放弃、会话锁、审计（便宜模型读改动写摘要；现在由强模型直接看真实改动复核）。旧版的代码在 `auto-1.1` 分支。

## 测试

`npm test` = 编译 + `node --test dist/test/*.test.js`。假的 claude / codex / dsh 程序（参数和输出格式跟真的一样）和假的模型接口，覆盖快照、账本、接力本、交接识别、调度、额度用完换人、复核、退回、群聊投票、网页接口。`test/accept.test.ts`、`test/guard.test.ts` 是 2026-09-25 审查的反例（复核结论的写法、验收、快照读不出来、配置坏了、退回的任务清单、换人确认、调度锁、内置小代理的路径、网页切换项目的旧响应），改这些地方要先让它们照样过。假工具测试过了不等于真实工具验收过了。

测试环境变量：`RELAY_HOME`（数据目录）、`RELAY_LOGIN_PATH=off`、`RELAY_SCAN_APPS=off`、`RELAY_AUTODETECT=off`、`RELAY_TERMINAL=off`、`RELAY_CLIPBOARD=off`、`RELAY_RETRY_MS`（网络抖动后隔多久再试）。
